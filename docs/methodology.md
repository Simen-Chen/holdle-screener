## 总体框架：三层概率优势

```
选好  →  等好  →  管好
（企业质量）（时机）（风险控制）
```

| 层 | 解决的问题 | 本仓库的实现状态 |
|---|---|---|
| 选好 | 别把烂公司放进池子 | 部分实现。靠人工挑的成熟公司池（`universe.json`，184 只 / 11 行业）近似，财务指标六维筛选未实现 |
| 等好 | 什么时候买 | 完整实现，见 `rules.py` 和 `engine.py` |
| 管好 | 什么时候卖、买多少 | 完整实现，三级止损加周K低点加仓位约束 |

这三层是串联的，缺一层整个优势就不成立。特别是「选好」这一块，本仓库是最大的缺口，用成熟公司池近似属于工程妥协，不是方法论原意。

## 等好：三重闸门

买点必须同时满足三个条件。这是整套体系的核心，也是最容易被简化掉的部分。

### 状态A（月线方向）

```
状态A  ⟺  月线 MACD 的 DIF > 0  且  DEA > 0  且  柱 > 0
```

MACD 参数是 `(12, 26, 9)`。柱 = `2 × (DIF − DEA)`，这是通达信口径，注意跟 `DIF − DEA` 的写法差一倍。

含义上是：月线级别上，中短期均线在长期均线之上，而且动能还在增强。

为什么用月线？因为月线能过滤掉绝大部分噪音。日线级别的状态A 满大街都是，月线级别的很少，这正是「等」的价值所在。

代码：`rules.is_state_a()`

### 前置校验（月K趋势结构）

```
月K 低点逐月抬高  且  月K 高点逐月抬高
```

逐月比较，当月没走完就忽略当月，默认实际比较 3 个完整月。任一项不成立就直接放弃，不看后面的信号。

为什么要有这一层：状态A 只反映动能，不反映结构。一只刚从深跌里反弹的票也可能出现「柱转正」，但它的月K 是低点越来越低。那不是趋势，是反弹。前置校验挡的就是这类。

代码：`rules.precheck()`

> 回看长度（默认 3 个完整月）是个解释性选择，方法论原文没有精确规定。取值偏严会把一些真实信号判掉。

### 第一根红柱（时机）

两个场景，满足任一即可。

| 场景 | 定义 | 含义 |
|---|---|---|
| 场景一 · 由绿转红 | 上月柱 < 0，本月柱 > 0 | 动能刚翻正 |
| 场景二 · 由矮变高 | 连续多月（默认 ≥2）递减后，本月柱 > 上月柱 × 1.10 | 动能由衰减转为重新增强 |

几个实现细节，都是踩过坑才加的：

- 容忍微升。递减过程中允许出现极小的噪音反弹（不足阈值），不打断「连续递减」的判定。
- 不重复触发。如果上一个月本身就已经达触发线，那信号属于上个月，本月不再重复报。
- ×1.10 这个阈值纯粹为了过滤噪音。取 1.0 会把大量「柱从 −0.001 变到 +0.0001」的伪信号放进来。

代码：`rules.recent_first_red_bar()`

### 入场闸门

```
入场闸门  =  状态A  ∧  前置校验  ∧  第一根红柱
```

三者同时成立，才进入下一阶段，也就是日K流程。

注意「进入入场期」不等于「可以买入」，这是两个概念，见下面「买点与失效」一节。

### 参考价 H

信号成立后的次月起，切换到日K：

1. 等价格冲高，形成一个短期高点
2. 等它回撤，并且回撤期间日K 出现绿柱
3. 那个高点就成为参考价 H

H 的作用不是「到 H 就买」，而是「突破 H 才买」。这是把追高变成等确认的关键设计。

代码：`rules.find_reference_high()`

> 口径说明：方法论原文只说「等待价格冲高，形成短期高点 H」，没规定 H 取哪一个高点。
> 当前实现取入场窗口内第一个满足「局部高点 + 有真回撤 + 回撤期间出绿柱」的高点。
> 局部高点的比较窗口以入场窗口左边界截断，也就是说窗口内最早几根K线也可以参选。
> 如果认为应该取窗口内最高点，改动点只有这一处函数。

### 买点与失效

```
买点  ⟺  收盘价 > H   （在失效期之前）
```

失效期 60 天，可配 50 到 60。H 形成后 60 天内不突破，这次入场就作废，回到等待状态。

判定用收盘价，不用盘中最高价。盘中突破、收盘跌回是常见的假突破。

为什么「突破 H 之后又跌回、再突破」不算买点：突破那天如果不在场，就没法判断突破之后已经走了多远。现价可能只比 H 高 1%，也可能先冲到 +30% 再回到 +1%。这两种情形买进去完全是两回事，而数据里看不出区别。分不清就不做。

代码：`engine.decide()` 的 BUY / CANCEL 分支，以及 `engine.analyze()` 里的 `h_broken_date`

### 重新入场规则

止损离场后，允许在同一轮状态A 内重新入场，但有约束。

| 规则 | 内容 |
|---|---|
| R1 | 重新入场的价格必须高于上一次止损离场价 |
| R2 | 必须走完整的入场流程：重新等信号，等回撤，突破 H |
| R3 | 同一轮状态A 内最多重新入场 2 次 |

为什么 R1 要求高于离场价：如果价格比上次止损位还低就买回来，等于承认上次止损是错的，那止损规则就失去了意义。

R2 有个实验性开关 `enable_r2_reentry`（止损后重入不再要求新的第一根红柱），默认关闭。

## 管好：风控

### 三级止损

| 阶段 | 止损线 |
|---|---|
| 刚入场 | 入场价 P × 0.80 |
| 浮盈 > 20% | 上移到 P × 0.90 |
| 浮盈 > 30% | 上移到 P，保本 |

代码：`rules.stop_line()`

### 周K有效低点

浮盈达到一定阶段后，止损规则切换为「跌破周K有效低点即离场」。

原版是回撤出周K绿柱、随后创新高，该低点成为参考价。本仓库用摆动低点窗口法近似，默认左右各 3 周。

这是个近似实现，不是精确还原。极端行情下可能有几个百分点的偏差。

代码：`rules.weekly_effective_low()`

### 仓位约束

| 约束 | 值 |
|---|---|
| 持股数 | 5 只（总资金 ÷ 5 = 单只额度） |
| 同行业上限 | ≤ 2 只 |
| 权重 | 等权重 |
| 建仓方式 | 一次性建仓，不加仓 |

为什么同行业不超过 2 只：月线级别的状态A 信号本身有行业聚集性，同一板块常常一起走强。不限制的话，5 个仓位可能全压在同一个行业上，分散就名存实亡了。

代码：`engine._sector_count()` / `engine._size_order()`

## 数据完整性

这一层是工程问题，不属于方法论，但少不得。任何指标算错都能让账户亏钱，所以数据本身先过闸。

`engine.analyze()` 对每个标的做两项体检，任一项不过，该标的这次就完全不参与判定：

| 检查 | 抓什么 | 阈值 |
|---|---|---|
| 日K单日跳变 | 复权失败的指纹。拆股在日线上必然是单日跳空 | ±50% |
| 跨周期末值一致 | 月线复权、周线不复权这类隐蔽的坏数据 | 5% |

两个设计要点。一是只用日K判跳变，不用月K，因为月线 −39% 可能是真实的逐步下跌，拿月线判会把真行情误杀。二是坏数据加上持仓触发止损，仍然不卖。宁可不动，不可乱动，等数据恢复再判。

## 解释性选择清单

下面这几处，方法论原文没有精确规定，本仓库做了明确选择。如果你不同意，这些就是你要改的地方。

| # | 议题 | 当前选择 | 改动点 |
|---|---|---|---|
| 1 | 参考价 H 取哪个高点 | 窗口内第一个满足条件的 | `rules.find_reference_high()` |
| 2 | 前置校验回看长度 | 3 个完整月，忽略当月 | `config.rules.precheck_lookback_months` |
| 3 | 突破后又跌回、再突破 | 不算买点 | `engine.analyze()` 的 `h_broken_date` |
| 4 | 场景二能否用于首次入场 | 可以（原文只在止损重入处提场景二） | `engine.decide()` |
| 5 | 周K有效低点 | 摆动低点窗口近似 | `rules.weekly_effective_low()` |
| 6 | 失效期 50 还是 60 天 | 60，更宽容 | `config.rules.breakout_deadline_days` |

## 没有实现的部分

- 基本面六维筛选（ROE / 毛利率 / 净利率 / 现金占比 / EPS）。这是最大的缺口
- 精确的周K有效低点
- 长周期历史回测，现在只有指标对拍校验
- 盘中实时判定。这是个 EOD 系统，收盘后才跑
- 滑点、点差、流动性建模
